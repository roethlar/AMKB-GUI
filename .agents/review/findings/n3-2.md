# n3-2: The write-capable API does not enforce the identity approval

**Severity**: HIGH — raised by the 2026-07-25 `openreview codex` pass
over `16901d8..abf32d7`.
**Status**: Verified
**Branch**: `neon-80-support` (worked in place)
**Commit**: see the `n3-2:` commit

## Evidence

am_configurator/hid_transport.py:364 — HidSession accepts an arbitrary raw path and send() writes without requiring WriteApproval; the validated handle was already closed at line 288.

## Predicted observable failure

A caller can bypass approval entirely, or a device swapped after validation can occupy the same OS path and receive writes intended for the confirmed keyboard.

## What

`WriteApproval` was built and then never made load-bearing. Validation and
transmission also happen on different handles, so the identity checked is not
the identity written to.

## Approach

`HidSession` is now `_RawSession`, private, with no public path-taking session
of any kind. Transmission goes through `open_approved(approval)`, which opens
the device, re-reads the Vial identity **on the handle it returns**, and hands
back a session only if that identity still matches the approval. The handle is
never closed and reopened in between, so nothing can be substituted inside the
window. `WriteApproval` also carries `model_uid` now, so the re-check compares
the firmware identity and not only the path.

The reviewer's suggestion: Expose an approved-session operation that opens the path, revalidates identity and approval on that same handle, and keeps it open through transmission; keep unrestricted raw sending private.

## Reopen round 1 — 2026-07-25

`codereview codex` returned **reopened** with two distinct holes, both real:

1. `open_approved` returned an already-open session, but `_RawSession.__enter__`
   reopened unconditionally. The ordinary `with session:` idiom therefore
   replaced the validated handle with a second, unchecked one — defeating the
   entire re-validation the fix was built for. `__enter__` is now idempotent.
2. `WriteApproval` is a public dataclass, so a caller could construct one with
   every field correct and `open_approved` would honour it; the confirmation
   string was never re-checked either. An approval now carries a module-private
   token that only `approve_write` can attach, and `open_approved` re-checks
   both the token and the confirmation.

Red-proof: reopening unconditionally fails
`test_using_the_session_as_a_context_manager_keeps_the_checked_handle` with
`1 != 2 : the validated handle was reopened`; dropping the token check fails
`test_a_forged_approval_is_refused`. Both verified, then restored.
