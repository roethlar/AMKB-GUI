# cl-19: Device rescan drops the trusted dynamic-layout signature

**Severity**: MEDIUM — a normal device rescan can silently disarm the
legacy-profile layout mismatch gate and allow a configuration authored for one
dynamic layout to reach another.
**Status**: In progress
**Branch**: —
**Commit**: pending

## Evidence

- `am_configurator/web/app.js:4839-4879` rebuilds `state.devices` from shallow
  discovery and carries forward deep `key_layout` and macro limits, but not the
  deep `descriptor` that owns the canonical keymap signature.
- The shallow descriptor is built without a dynamic layout, so its keymap
  signature is unknown even when the carried `key_layout` remains present.
- `am_configurator/web/app.js:4672-4686` reads only
  `device.descriptor.keymap.signature` when synchronizing a legacy document.
- `am_configurator/web/app.js:367-389` clears current layout evidence, omits the
  now-missing signature, and adopts the server's unresolved result.
- With more than one remembered layout, `am_configurator/profile_metadata.py:
  263-270` returns no evidence. `am_configurator/server.py:4137-4182` then has
  no expected signature to compare and cannot reject a different live layout.

The intake trace followed the actual Read → shallow Scan → document Sync →
Preflight/Write path and confirmed the deep descriptor is the only state lost;
the existing browser guard checks call ordering but never exercises a rescan or
null signature.

## Predicted observable failure

Open a legacy Neon profile with layout A selected while two layouts are
remembered, open the Device dialog to rescan, then perform an action that
resynchronizes the document. Layout evidence becomes unavailable. A subsequent
preflight and direct write to layout B can both proceed because `expected` is
`None`, violating the slice's zero-transport mismatch guarantee.

## What

The rescan merge preserves the dynamic geometry bytes but discards the
canonical descriptor derived from those bytes. The later trust path consults
the discarded descriptor rather than rebuilding it or preserving the trusted
deep result.

## Approach

Preserve or deterministically rebuild the deep descriptor whenever shallow
discovery carries forward a validated `key_layout`; never retain a signature
without its exact layout. Add a behavioral rescan guard that begins with a deep
layout, merges shallow discovery, resynchronizes, and proves a mismatched live
layout still fails before any driver transmission.
