**Status**: Verified (not re-reviewed)

## Evidence

am_configurator/server.py:2039 - /api/device/read serializes HidDeviceInfo with asdict; its bytes path is not JSON-serializable, while derived product_id is omitted.

## Predicted observable failure

Clicking Read keymap & macros for a Neon finishes the HID reads but returns a generic HTTP 500, so the UI can never load the device workspace.

## What

See the pass summary in `.agents/review/index.md`: the protocol modules are
sound in isolation and the seams between them and the existing application were
not built. This finding is one of those seams.

## Approach

Every device response now goes through the transport's JSON projection, and
the HID device contract carries the route fields that do not apply to HID as
explicit null values.

## Files changed

`am_configurator/hid_transport.py`, `am_configurator/server.py`, and
`tests/test_hid_transport.py`.

## Guard proof

response contract. The repair was red-proven as part of `48398c9`.
