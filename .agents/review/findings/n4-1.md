# n4-1: The udev install command cannot write its root-owned destination

**Severity**: HIGH — the documented remedy fails for every Linux user who
follows it.
**Status**: Verified
**Branch**: `neon-80-support` (worked in place)
**Commit**: see the `n4-1:` commit

## Evidence

`docs/neon-80-linux.md:24` and `am_configurator/hid_transport.py:117` both
recommended `sudo <application> --print-udev-rule > /etc/udev/rules.d/...`.

## Predicted observable failure

The shell opens a `>` target as the invoking user, *before* `sudo` runs, so the
redirect into a root-owned directory fails with permission denied regardless of
how the application is elevated. The rule is never installed and the Neon 80
stays inaccessible — the exact outcome this whole remedy exists to prevent.

## What

Self-inflicted, and recent: this wording was introduced by the n3-3 repair,
which fixed the AppImage problem and replaced it with a shell problem. The
guard written alongside it asserted only that the text mentioned
`--print-udev-rule`, which the broken form does.

## Approach

Both surfaces now pipe into `tee`, elevating the write rather than the reader:

    ./AM_Configurator.AppImage --print-udev-rule | sudo tee /etc/udev/rules.d/60-am-neon-80.rules >/dev/null

The documentation explains why, so the next person does not "simplify" it back.

## Files changed

- `docs/neon-80-linux.md` — both invocations plus an explanatory note.
- `am_configurator/hid_transport.py` — the runtime permission remedy.

## Guard proof

`tests/test_packaging.py::test_the_udev_install_command_elevates_the_write_not_the_reader`
checks both surfaces. Restoring the redirect form fails it.

**The guard was initially not running at all.** It was appended below the
module's `if __name__ == "__main__":` block, so it sat outside any test class
and was never collected — the suite count stayed at 30 and the red-proof passed
against a perturbed document. Re-parenting it into the class raised the count to
31 and the red-proof then failed correctly. A test that is not collected is
worse than no test.
