# cl-12: Sessionless supersession starts only after media decode

**Severity**: LOW — stale full-render requests still perform the bounded but
potentially expensive complete media decode before observing a newer epoch.
**Status**: In progress
**Branch**: —
**Commit**: pending

## Evidence

- `am_configurator/media_composition.py:1480` calls `decode_media(payload)`
  without its supported `work_check` callback.
- `am_configurator/media_composition.py:1946-1962` creates and fully decodes the
  session before registering the render epoch.
- Before LSR-2, the renderer registered the epoch first and passed its check to
  `decode_media`, allowing stale animated decodes to abort between frames.

The intake concurrency reproduction started epoch 1, held it immediately after
its full decode, and completed epoch 2. Both decode calls received no
`work_check`; epoch 1 only raised `MediaRenderSuperseded` after its decode had
already completed.

## Predicted observable failure

Dragging a transform can queue several sessionless full renders. Every stale
request may read and decode a media file with hundreds of frames before it
learns that a later epoch replaced it. On the threaded server this increases UI
latency and peak memory while producing no useful output.

## What

LSR-2 preserved final stale-publication rejection but accidentally moved the
first cancellation point from before decode to after decode. The output remains
correct; cancellation responsiveness regressed.

## Approach

Register the destination-scoped epoch before transient decoding and pass its
check into `decode_media`. Resolve the destination identity using only validated
source-independent request fields before decode, then retain the existing exact
render preparation and publication checks.

## Guard proof

`tests/test_media.py` —
`test_sessionless_supersession_interrupts_decode` starts epoch 1 in a controlled
decoder, registers and completes epoch 2 for the same destination, and requires
epoch 1 to receive a real work check and abort through it before the simulated
expensive decode completes.

Proof:

- Test-first red: epoch 1 received no work check (`[False]`) and completed its
  decode before later raising `MediaRenderSuperseded`.
- Focused green: epoch 1 received the check, aborted inside it, never completed
  the simulated decode, and epoch 2 completed normally.
- Mutation proof: restoring only the pre-repair production behavior made the
  guard fail again because epoch 1 received no check; restoring the repair
  returned it green.
- Affected suites: 246 tests passed with 3 skips across media, app, device
  mapping, and Library coverage.

  Python compilation, all seven JavaScript syntax checks, and `uv build`
