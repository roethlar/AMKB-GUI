# cl-13: Expired media preview sessions cannot recover

**Severity**: HIGH — an ordinary five-minute idle period or bounded-LRU
eviction permanently breaks Preview and Source for the open media draft until
the user cancels and discards it or imports the file again.
**Status**: In progress
**Branch**: —
**Commit**: pending

## Evidence

- `am_configurator/web/app.js:2718-2721` returns any cached
  `preview_session_id` without revalidating it.
- `am_configurator/web/app.js:3046-3055` and `am_configurator/web/app.js:2808-2816`
  reuse that ID for render and source-frame requests; neither failure path
  clears it.
- `am_configurator/web/lighting_workspace.js:704-719` can set a preview session
  but has no event that invalidates only the expired session while preserving
  the draft.
- `am_configurator/media_composition.py:34,1537-1549` deliberately expires
  sessions after five minutes and evicts them from a two-entry LRU, returning
  `This media preview session is no longer available.` for the stale ID.

The browser/server contract was independently checked against the reviewed
commit after intake: the cached ID survives render failure, while every retry
short-circuits before creating a replacement session.

## Predicted observable failure

Import media and create a preview, then either leave it idle for more than five
minutes or let two newer preview sessions evict it. Preview sends the expired
ID and fails. Every later Preview sends the same ID and fails again; Source
frame loading also remains unavailable. Cancel or re-import is the only current
recovery, which discards the user's active framing workflow.

## What

LSR-4 introduced retained preview sessions so Source can request exact decoded
frames. The frontend treats the retained ID as permanent even though the server
contract intentionally makes it short-lived.

## Approach

Add a reducer-owned, identity-checked session-invalidation event that clears
only the expired ID and preserves the media draft and accepted Board result.
Have render detect the server's exact unavailable-session response, invalidate
the request's ID, and retry once through normal session creation. Source-frame
failure invalidates the same ID so the next Preview can recover. Extend the
native audit to evict the active session and prove replacement plus successful
render in the real WebView2 integration path.
