# n567-6: Vial macro encoding discards macro slot identity

## Evidence

am_configurator/vial_macros.py:147 - encoding uses list order and ignores original_key; line 200 decodes original_key from the first event instead of the M1-M16 slot.

## Predicted observable failure

Gapped or reordered macros execute under the wrong key assignment, and readback returns event codes plus empty slots as macro identities, causing verification mismatches even when bytes were written correctly.

## What

See the pass summary in `.agents/review/index.md`: the protocol modules are
sound in isolation and the seams between them and the existing application were
not built. This finding is one of those seams.

## Approach

Encoding now places each macro in the device slot named by its token, rejects
duplicate and out-of-range claims, and preserves list position only for
tokenless serial-family profiles. Read-back assigns the token for the slot read.

## Files changed

`am_configurator/vial_macros.py` and `tests/test_vial_macros.py`.

## Guard proof

Gapped, reordered, round-trip, read-back-token, duplicate, out-of-range, and
tokenless-profile guards cover the slot table. List-order encoding and
first-event decoding were each red-proven before restoration.
