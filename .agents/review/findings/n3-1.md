# n3-1: The Vial UID is used as instance identity instead of model identity

**Severity**: HIGH — raised by the 2026-07-25 `openreview codex` pass
over `16901d8..abf32d7`.
**Status**: Verified
**Branch**: `neon-80-support` (worked in place)
**Commit**: see the `n3-1:` commit

## Evidence

am_configurator/hid_transport.py:280 — the FE 00 value becomes the device address, although Vial returns the firmware's compile-time VIAL_KEYBOARD_UID; every unit running the same Neon firmware reports the same value, while the model gate at line 290 ignores it and checks only the display name.

## Predicted observable failure

Two attached Neon 80 units produce identical addresses, so find() selects whichever enumerates first and a read or write can target the wrong keyboard.

## What

The earlier fix in 51c1e10 replaced a serial shared by *all Vial boards* with a
UID shared by *all units of this model*. Strictly better, still not instance
identity, and the approval-transfer risk between two Neon 80s survives.

## Approach

Model identity and instance identity are now separate fields.
`firmware_uid` and `protocol_version` join `definition_name` as **model**
identity and are checked for coherence before a device is called writable.
`address` becomes an opaque token derived from the OS device path — the only
per-endpoint value available — via `endpoint_address`.

This is the third addressing scheme, and the progression is worth recording: the
USB serial is shared by every Vial board, the Vial UID is shared by every unit
of a model, and only the device path distinguishes two attached units. Each of
the first two looked unique and was not.

The reviewer's suggestion: Use the Vial UID, supported protocol version, and coherent definition fields to validate the model; use an opaque connection-scoped HID-path token to address a physical endpoint.

## Guard proof

`tests/test_hid_transport.py::AddressIdentityTests`. The decisive test is
`test_two_units_of_the_same_model_get_different_addresses`: two endpoints with
identical serial *and* identical firmware UID, differing only by path. Restoring
the UID-based address fails it with
`'05AC:024F:d47af38a35b8ed73' == '05AC:024F:d47af38a35b8ed73' : two units of one
model must not share an address`, and fails
`test_an_address_leaks_neither_shared_identifier` alongside it. Verified, then
restored.

`test_an_approval_does_not_transfer_between_units` states the consequence
directly: an approval for one unit must not match another unit of the same
model.

## Coder dispute (if any)

None. Admitted. Verification limited: this repository has one Neon 80, so a
collision between two units cannot be observed here. The reasoning is sound —
Vial's keyboard UID is a firmware build-time constant used to match a board to
its definition, which is inherently per-model — and the previous address scheme
was already corrected once for the same class of error. Treat 'per-model, not
per-unit' as the working conclusion; confirming it needs a second board.

## Known gaps
