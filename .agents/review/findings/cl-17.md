# cl-17: Effect parameter changes leave timeline LED thumbnails stale

**Severity**: MEDIUM — the Board and Apply arrays update correctly, but the
shared timeline continues to show the previous effect colors indefinitely,
misrepresenting the accepted output during the slice's primary interaction.
**Status**: In progress
**Branch**: —
**Commit**: pending

## Evidence

- At reviewed commit `246da643e95dbc2fc390507264e228cc75051292`,
  `am_configurator/web/app.js:4058-4063` binds the six normal effect controls
  to `regenerateLocalAnimationDraft({renderWorkspace:false})`; no trailing
  event requests a full workspace render.
- `am_configurator/web/app.js:3858-3861` handles that partial path by calling
  only `renderLightingBoardProjection()` and
  `updateLocalAnimationDraftStatus()`.
- `am_configurator/web/lighting_workspace.js:1375-1397` repaints physical
  Board pixels and frame selection metadata, but never updates a frame item's
  `.frame-thumb` colors.
- `am_configurator/web/app.js:4345` creates each thumbnail's LED swatches only
  inside `renderLightingEdit()`. No other application writer updates those
  swatches.

Direct inspection after intake reproduced the broken ownership chain: the
accepted `BoardFrameSet` changes, the partial projection uses its new active
frame for Board pixels, and the already-mounted timeline swatches retain their
old inline backgrounds.

## Predicted observable failure

Select Pulse, Hue cycle, Sweep, or Shimmer, then change Minimum brightness,
Color rotations, Sweep direction/band width, Shimmer depth, or Pattern seed.
The Board immediately shows the new effect and Apply will clone those new
arrays, but every timeline LED miniature keeps the previous parameter's colors
until an unrelated full render such as frame-count change, duration change,
tool switch, Apply, or Cancel.

## What

The focus-preserving partial repaint updates only the current physical Board
frame and timeline selection state. Timeline thumbnails are also projections
of the exact accepted frame set, but they were left owned exclusively by the
full HTML render, so normal live parameter changes split the UI between two
different outputs.

## Approach

Extend `paintBoardProjection` to repaint the mounted thumbnail swatches from
the same selected `BoardFrameSet` used by the Board. Keep the partial repaint
path so slider input does not rebuild the workspace or steal focus. The update
must address every mounted frame item, clamp to its existing swatch count, use
canonical frame colors only, and leave selection/accessibility updates intact.
