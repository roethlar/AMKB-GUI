# cl-16: Interactive framing never uses the selected-frame render tier

**Severity**: MEDIUM — every small framing adjustment waits on a full
multi-frame render, making long GIF editing serial and visibly stale despite
the approved fast-preview contract and existing backend endpoint.
**Status**: Verified
**Branch**: —
**Commit**: `1b09a2a7d6da087187efbf125c9480cb457e7f46`

## Evidence

- The reviewed browser tree has no caller for
  `POST /api/library/items/<catalog-id>/render-frame`; the only application
  occurrence is the server route.
- `am_configurator/web/app.js:198-204` creates one scheduler whose runner is
  `renderMediaCompositionPreviewAttempt`.
- `am_configurator/web/app.js:3292` posts only to the full `/render`
  endpoint.
- Transform, effect, preset, and destination changes all reach that same full
  render scheduler through `requestMediaCompositionRender`.
- `am_configurator/web/lighting_workspace.js:807` supports
  `FRAME_RENDER_STARTED`, but this range never dispatches it.
- The approved LSR-5 plan explicitly requires exact selected-frame requests
  with one in-flight and one latest pending request, followed by a short idle
  debounce for the full sequence that alone enables Apply.

TokenSave and direct pinned-tree search after intake confirmed the
`render_frame` backend method exists while no browser caller exists.

## Predicted observable failure

On a long GIF, every drag, keyboard nudge, preset, or destination adjustment
leaves Board showing the previous accepted LEDs until the whole sequence
finishes. Two quick adjustments serialize behind two full renders, and Apply
stays disabled throughout. Latency scales with total frame count instead of
the selected frame.

## What

LSR-5 implemented debouncing and latest-only execution for the full sequence
but omitted the separate immediate selected-frame tier that the plan and
backend contract reserve for interactive truthfulness.

## Approach

Add a selected-frame scheduler with one running request and one latest pending
request. Interactive transform/effect changes immediately render the current
playhead through `/render-frame` and publish only that exact Board frame.
After the latest selected-frame result is accepted, start or restart the short
bounded idle debounce for the existing full-sequence render. Only the exact
accepted full sequence may satisfy Apply; selected-frame publication never
launders partial work into the document. Preserve Source/Board timeline
identity, stale context rejection, preview-session recovery, and cancellation
across both tiers.
