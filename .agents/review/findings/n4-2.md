# n4-2: The Neon editor fabricates a layout while geometry is unavailable

**Severity**: MEDIUM — a user can paint against LED positions that do not exist.
**Status**: Verified
**Branch**: `neon-80-support` (worked in place)
**Commit**: see the `n4-2:` commit

## Evidence

`am_configurator/web/app.js:1429` — absent served geometry silently became an
identity map. Boot rendered before the capabilities request, which was bundled
with the optional AI status calls in `loadAiConfig`.

## Predicted observable failure

On startup the Neon axial editor renders a sequential 1:1 layout instead of its
19x6 geometry. If the capabilities call is slow or fails, that stays editable:
the user paints and saves against a fabricated layout, and the saved document
addresses LED positions the device does not have.

## What

The Neon deliberately carries no embedded maps — N4b moved that authority to the
server — which means it has *no* fallback worth having. The identity map was
inherited from families that never need it, and it is precisely the kind of
plausible-looking wrong answer that is worse than an error.

## Approach

Two changes. A family with no embedded maps and no served geometry now renders
an explicit loading-or-unavailable notice instead of an editor. And device
geometry is fetched on its own, awaited before the first render, rather than
riding the AI bundle — geometry decides whether the editor can exist at all and
has no business waiting on an optional AI status call.

## Files changed

- `am_configurator/web/app.js` — the render guard, `geometryUnavailableNotice`,
  `loadDeviceGeometry`, and its await in `boot`.

## Guard proof

`tests/test_app.py::NeonEditorGeometryGuardTests`. Restoring the identity-map
fallback fails the first test; moving the geometry load back after `render()`
fails the second. Both verified, then restored.

## Coder dispute (if any)

None.

## Known gaps

The guards are source-text assertions, because `app.js` is a browser script that
cannot be imported in Node. That is the same limitation the rest of the app.js
coverage lives with.
