# cl-24: Closing import review retains the review destination

**Severity**: LOW — closing a non-mutating import review can redirect the next
edit to a different LED track than the user was editing.
**Status**: Open
**Branch**: —
**Commit**: —

## Evidence

- `am_configurator/web/app.js:741-783` switches to the imported lighting's
  destination but records no pre-review destination.
- `closeImportedLightingReview()` changes the destination only when the review
  target is unsupported by the document. AM 80 `head` and `axial` targets are
  both supported by Neon, so Close retains the review target.
- `tests/web/lighting_shell.test.js:959-994` currently asserts that retention
  for the Neon path, making the wrong interaction load-bearing.

## Predicted observable failure

While editing Neon Head, open AM 80 lighting whose review switches to Per-key,
then press Close. Although the review promises the open profile was not changed,
the editor remains on Per-key and the next paint or Apply operates on the wrong
track relative to the user's pre-review context.

## What

The review owns a temporary destination but Close has no saved document
destination to restore when both destinations are valid.

## Approach

Capture the current document destination when imported-lighting review opens.
On Close, restore that exact target when the open document still supports it;
otherwise fall back to the document's first supported target. Exercise the full
open/switch/close flow in the browser test rather than source-matching it.

## Files changed

- `am_configurator/web/app.js` — retain and restore the pre-review destination.
- `tests/web/lighting_shell.test.js` — execute the open/close flow and fallback.
- Review/state/plan records — finding and qualification state.

## Guard proof

Pending repair. Required proof: the executable shell test must fail against the
current retention behavior and pass only when Close restores the captured
target, with unsupported captured targets falling back deterministically.

## Coder dispute (if any)

None. Close is a non-mutating boundary and should restore the editor context it
temporarily replaced.

## Known gaps

This changes transient editor context only; imported frames, the open document,
Undo/Redo, Library state, and hardware remain untouched. Per-finding Claude
verification is explicitly waived; local mutation proof, the complete gate,
native audits, and exact-head CI are authoritative.
