# n567-9: Device-reported macro byte capacity never reaches the editor

**Severity**: MEDIUM — 2026-07-26 `openreview codex` over

## Evidence

am_configurator/web/lighting_targets.js:65 - freezeSpec drops macroBufferBytes, while app.js:1240 presents the static 6677 value as an event limit rather than the connected device's byte budget.

## Predicted observable failure

Users can build a profile the UI says fits but which is rejected only during write preflight, and firmware reporting a different capacity is never reflected in the workspace.

## What

See the pass summary in `.agents/review/index.md`: the protocol modules are
sound in isolation and the seams between them and the existing application were
not built. This finding is one of those seams.

## Approach

`freezeSpec` now retains `macroBufferBytes` and `keysPerLayer`, and the
cross-language drift guard compares both. The device transport now returns the
macro table together with whether the device reported limits and the exact
count and byte capacity. The read route publishes those values on the deep
device record; the browser overlays them onto the active Neon family spec and
preserves them across shallow rescans.

The macro editor meters the exact Vial buffer encoding: one terminator for every
device slot, three bytes per key event, and four bytes for every nonzero delay.
Import, text conversion, manual additions, recording, and delay edits are
checked before mutation. Serial families retain their existing event-count
limits.

## Guard proof

The cross-language drift guard fails if either static field is dropped from the
browser mirror. A fresh production-only reverse patch made the four focused
Python guards fail with two failures and two errors, and made four browser
guards fail. Byte-exact restoration returned the focused completion guards to
green: 137 Python tests and 31 browser tests.

The guards cover retaining the reported capacity without a second query,
publishing it through the authenticated device-read route, distinguishing a
reported zero from an absent report, overlaying and retaining the deep limits,
filtering macro tokens to the reported count, exact byte usage, and every editor
mutation gate. The full repository gate passes: 564 Python tests (one skipped),
54 browser tests, compile and JavaScript syntax checks, and both distribution
builds.
