# cl-23: App-native round-trip audit can pass before reopen

schema-v2 native report on every platform.
**Status**: Verified
**Branch**: —

## Evidence

- `am_configurator/media_framing_audit.py:1035-1069` saves the already-open
  blank CyberBoard document and immediately reopens identical bytes.
- The saved and current lighting fingerprints, product ID, synchronized state,
  and empty Undo stack already satisfy every post-reopen assertion before
  `readFiles()` runs.
- `am_configurator/web/app.js:605-668` catches import errors and reports them by
  toast without rethrowing or writing a console error, so the remaining console
  assertion cannot distinguish a swallowed import failure.

## Predicted observable failure

Breaking app-native import classification, normalization, compatibility, or
merge before `state.config` is replaced still lets source and frozen schema-v2
native audits report `app_native_round_trip` as passing. Release qualification
therefore claims a round trip it did not execute.

## What

The audit's pre-import and expected post-import states are identical, making its
round-trip check non-load-bearing for the failure path it is supposed to guard.

## Approach

After capturing the saved bytes, mutate the open document through the real Undo
path and prove its fingerprint differs from the saved payload before reopening.
Require the imported filename as an additional completion signal, then require
the saved fingerprint and cleared Undo stack after import. Prove the native
audit fails when the app-native import path is deliberately short-circuited.
