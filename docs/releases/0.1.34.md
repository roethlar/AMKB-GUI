# AM Configurator 0.1.34

AM Configurator 0.1.34 is a normal public release of the independent desktop
editor for Angry Miao keyboard profiles. It is an independent community project
and is not affiliated with or endorsed by Angry Miao.

## Highlights

- Every launch opens Keymap. Saved routes and startup links cannot strand the
  application in Lighting or Settings.
- Keymap uses model-shaped, correctly sized keys rather than a raw matrix.
- The macro editor supports exact event recording, manual event editing,
  compatible-profile import, and deterministic text-to-keystroke conversion.
- Lighting is one cohesive Studio with Paint, Source, and Animate tools.
  Multi-LED keys remain individually labelled, including all three Relic 80
  spacebar LEDs.
- GIF, PNG, and BMP sources can be panned, zoomed, or stretched inside the
  destination layout. Still images can use local Pulse, Hue cycle, Sweep,
  Shimmer, and Move & zoom effects.
- Imported media, manual lighting, generated lighting, and compatible keyboard
  profiles can be saved in one mixed Library. Removal is reversible.
- AI is optional and off by default. Its controls and setup disappear when the
  switch is off, and no local-model discovery occurs in that state.
- The version is available through the quiet About link rather than occupying
  the application header.

## What was actually qualified

The USB device transport and complete-write flow were live-tested on one AM
Neon 80 connected to macOS. The test covered device identity, keymap and macro
reading, a confirmed complete configuration write, and keymap/macro transport
verification. Neon firmware does not expose LED read-back, so lighting was
verified visually rather than claimed as a device read-back result.

CyberBoard, Relic 80, and AFA/AFA 2 adapters have fixture, protocol, geometry,
and automated regression coverage. They were not live-qualified on physical
hardware for this release.

The macOS package receives a native frozen-app smoke test. Windows and Linux
installers receive automated native smoke tests in their own GitHub-hosted
operating systems after packaging. They are not manually qualified on Windows
or Linux for this release.

The local Ollama path has automated coverage and maintainer acceptance with an
installed local model. Remote API adapters are experimental. Anthropic, OpenAI,
Gemini, xAI, Kimi/Moonshot, and DeepSeek are wired through the same constrained
recipe path but are not live-qualified with paid credentials for this release.

## Important device behavior

- A full write replaces keymaps, macros, and LED data together. Preserve a
  complete portable JSON or the original lighting media before writing.
- Neon firmware does not expose LED read-back. Reading the keyboard is not a
  backup of its current lighting.
- Neon requires its physical Esc+F2 unlock before a write. The application
  cannot press that combination for the user.
- AM Master, Vial, VIA, QMK Toolbox, or another configurator can hold the HID
  interface exclusively. Close competing applications before reading or
  writing.
- Device selection and reads do not write. The full write remains separately
  confirmed with the displayed device identity.
- A saved verified profile is local to that computer. Export JSON when moving
  between machines.

## Integrity and provenance

Compare the installer against `SHA256SUMS.txt`, then verify its free GitHub
build attestation:

```text
gh attestation verify <downloaded-file> --repo roethlar/AMKB-GUI
```

Hashes and attestations prove byte identity and workflow provenance. They do not
give the packages an Apple Developer ID or Windows Authenticode publisher
identity.

## Reporting a problem

Use the
[structured bug report](https://github.com/roethlar/AMKB-GUI/issues/new/choose)
and include the keyboard, firmware identity, operating system, application
version, operation, and exact installer filename. Remove API keys, device
serials, personal paths, and private macro or profile contents before posting.
